---

overall: 5/5 passed

all questions pulled from the right story which is the main thing being
tested. the "facts matched" numbers look mixed but that metric is just
simple substring checking so it misses a lot of correct answers that
use different words.

avg time per question was around 3 seconds. most of that is waiting for
gpt-4o-mini to respond (about 2.8 seconds), the actual vector search in
qdrant is super fast like under 100ms. this surprised me honestly, i
thought vector search would be the slow part but its the llm thats slow.

one thing i noticed - the easy question (q3) had the best facts matched
score (5/5) and the hard multi-hop question (q5) had lower (4/8). this
makes sense because harder questions need more pieces of information and
the llm might not fit everything into one answer.

things i noticed while testing:

- when i first ran ingest, it took about 15 seconds total for 72 chunks.
  not bad at all, and i only need to do it once

- the validate command ran all 5 questions back to back, total maybe
  15-20 seconds. each question around 3 seconds

- i tested a few other questions manually using the "ask" command too:
  - "who was vincent spaulding" -> correctly said he was john clay
  - "what is the blue carbuncle" -> correctly described the gem
  these werent in the validation set but worked fine

- i initially had k=3 (retrieve 3 chunks). i also briefly tested k=5
  but the answers didnt really improve and sometimes had more irrelevant
  stuff, so k=3 seems right for this corpus size

cost was cheap - total maybe $0.05 to $0.10 for all the embeddings and
llm calls combined. the embeddings were especially cheap, basically
pennies for 72 chunks.

overall validation passed successfully. source matching was 100% which
is the main metric. not bad for a first RAG system!
